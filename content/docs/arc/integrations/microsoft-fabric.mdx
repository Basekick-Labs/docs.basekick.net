Get Arc data into a Power BI report in Microsoft Fabric, entirely in the browser: no Power BI Desktop, no Windows machine, no gateway and nothing to install on Arc.

A Fabric notebook queries Arc's HTTP API, receives the result as Arrow, and writes it to a Lakehouse table. Power BI reads that table directly (Direct Lake), and a schedule keeps it current.

```text
Arc  ──POST /api/v1/query/arrow──▶  Fabric notebook  ──▶  Lakehouse table  ──▶  Semantic model  ──▶  Power BI report
       (Arrow, over HTTPS)          (scheduled)          (Delta, OneLake)      (Direct Lake)
```

<Callout type="info" title="Works with the Arc you run today">
The Arrow endpoint used here is in every Arc release since v25.12.1. For older releases, use the JSON variant [below](#older-arc-releases-json).
</Callout>

## Before you start

- **A Fabric workspace on a trial or Fabric capacity.** Notebooks and Lakehouses are not available on a Power BI Pro–only workspace.
- **Arc reachable from the internet over HTTPS.** The notebook runs in Microsoft's cloud, so it cannot reach an Arc on your laptop or private network.
- **A read-only Arc token**, limited to the databases the report needs. Never use an admin token here.

The steps use the demo dataset `weather_tracking.weather_observations` (three cities, a reading every few minutes). Replace it with your own database and measurement.

## 1. Create a workspace

In [app.fabric.microsoft.com](https://app.fabric.microsoft.com), open **Workspaces → New workspace**, name it, and under **Advanced** choose **Trial** (or a Fabric capacity) as the license mode. You can check the mode later under **Workspace settings → Workspace type**:

![Workspace settings showing the workspace type Fabric Trial](/img/arc-fabric/arc-fabric-new-workspace.png)

## 2. Create a Lakehouse

In the workspace, click **New item → Lakehouse**, name it `arc_lakehouse` and click **Create**:

![The New Lakehouse dialog with the name arc_lakehouse and Lakehouse schemas ticked](/img/arc-fabric/arc-fabric-new-lakehouse.png)

The Lakehouse opens empty. With **Lakehouse schemas** on (the default), tables go in the `dbo` schema. **New semantic model** stays greyed out until the Lakehouse has a table:

![The empty Lakehouse: Tables with an empty dbo schema, and Files](/img/arc-fabric/arc-fabric-empty-lakehouse.png)

## 3. Create a notebook

From the workspace, click **New item → Notebook**, then attach the Lakehouse in the notebook's Explorer with **Add data items**. (Opening the notebook from the Lakehouse attaches it for you.) Rename it `arc_to_lakehouse`:

![An empty notebook with arc_lakehouse attached in the Explorer](/img/arc-fabric/arc-fabric-notebook-attached.png)

## 4. Pull data from Arc

Use two cells, so the token is never visible in the code you share or screenshot.

**Cell 1, the token.** Collapse it afterwards (**⋯ → Hide input**):

```python
ARC_TOKEN = "<a read-only Arc token>"
```

**Cell 2, the query:**

```python
import requests, pyarrow.ipc as ipc

ARC_URL = "https://arc.example.com"
SQL = """
SELECT * FROM weather_tracking.weather_observations
WHERE time > now() - INTERVAL 30 DAY
"""

r = requests.post(f"{ARC_URL}/api/v1/query/arrow",
                  headers={"Authorization": f"Bearer {ARC_TOKEN}"},
                  json={"sql": SQL}, stream=True, timeout=300)
r.raise_for_status()
table = ipc.open_stream(r.raw).read_all()   # Arrow: columnar, exact types
print(f"{table.num_rows} rows from Arc")

spark.createDataFrame(table.to_pandas()) \
     .write.mode("overwrite").saveAsTable("weather_observations")
```

Click **Run all**. The cell prints the row count and writes the table:

![The notebook after a run: the token cell hidden, the query cell, Spark jobs succeeded and 12762 rows from Arc, and the weather_observations table with its columns in the Explorer](/img/arc-fabric/arc-fabric-notebook-run.png)

<Callout type="info" title="Refresh the Explorer">
The new table appears in the Explorer only after a refresh: **dbo → ⋯ → Refresh**.
</Callout>

The `WHERE time > now() - INTERVAL 30 DAY` filter keeps each run bounded: the whole result passes through the notebook's memory, so pull the window the report needs rather than the whole measurement. Any SQL Arc accepts works here, including aggregations, so you can also ship pre-aggregated data (for example hourly averages) instead of raw rows.

## 5. Create the semantic model

Back in the Lakehouse, click **New semantic model**, name it, and select `dbo → weather_observations`:

![The New semantic model dialog: Direct Lake semantic model named weather, workspace Arc Demo, dbo.weather_observations selected](/img/arc-fabric/arc-fabric-semantic-model.png)

The model uses **Direct Lake**: Power BI reads the table's files in OneLake directly, with no import step.

## 6. Build the report

From the semantic model, create a new report. For a temperature chart per city:

- **Line chart**: `time` on the X-axis, `temperature` on the Y-axis, `city` in the Legend.
- Set the Y-axis field to **Average**. Power BI defaults numeric fields to Sum, which adds up readings that share a timestamp.
- Filter by city in the **Filters** pane, or add a **Slicer** on `city`.

![The Power BI report editor: Average of temperature by time and city for Buenos Aires, London and Tokyo, with a city filter showing 4254 rows per city](/img/arc-fabric/arc-fabric-report-edit.png)

Save the report. In reading view:

![The saved report Weather in three cities in reading view](/img/arc-fabric/arc-fabric-report-view.png)

## 7. Schedule the refresh

In the notebook, open **Settings (⚙) → Schedule → Add schedule**, choose **Hourly** with an interval of 1, and **Save**:

![The notebook schedule panel: repeat hourly, every 1 hour, with start and end dates and time zone](/img/arc-fabric/arc-fabric-schedule.png)

Each run replaces the table with the latest window from Arc. An open report does not pick up the new data on its own: click **Refresh** in the report to see it.

## Older Arc releases (JSON)

Releases before v25.12.1 have no Arrow endpoint. Use the JSON one instead. JSON carries no column types, so convert the time column and check numeric types yourself: a float column whose values happen to be whole numbers comes back as integers.

```python
import requests, pandas as pd

r = requests.post(f"{ARC_URL}/api/v1/query",
                  headers={"Authorization": f"Bearer {ARC_TOKEN}"},
                  json={"sql": SQL}, timeout=300)
r.raise_for_status()
res = r.json()
pdf = pd.DataFrame(res["data"], columns=res["columns"])
pdf["time"] = pd.to_datetime(pdf["time"])

spark.createDataFrame(pdf).write.mode("overwrite").saveAsTable("weather_observations")
```

## Production notes

- **Keep the token out of the notebook.** For anything beyond a trial, store it in Azure Key Vault and read it at run time with `notebookutils.credentials.getSecret("https://<vault>.vault.azure.net/", "<secret-name>")`.
- **Least privilege.** The token sees what its permissions allow, nothing more. Give it read access to the databases the report uses.
- **Size the window.** Each run moves the whole query result. Bound it by time, or aggregate in SQL, to keep runs fast.
- **Failure alerts.** The schedule panel can email you when a scheduled run fails.

## What's next

- **Arrow Flight SQL (Arc 27.01.1).** Arc gains a native [Flight SQL listener](/arc/integrations/flight-sql/) for ADBC clients. Power BI ships a Flight SQL ADBC driver, which opens the way to a direct connector.
