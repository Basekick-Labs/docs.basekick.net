Install Arc directly on Linux using native packages (.deb, .rpm) or build from source.

<Callout type="idea" title="Latest Version">

</Callout>

## Prerequisites

- Linux (x86_64 or ARM64)
- 4GB RAM minimum, 8GB+ recommended
- systemd (for service management)

## Quick install

The following commands automatically fetch and install the latest Arc release.

<Tabs items={['Debian/Ubuntu', 'RHEL/Fedora', 'Arch Linux', 'Build from Source']}>
  <Tab value="Debian/Ubuntu">

**x86_64 (AMD/Intel):**

```bash
LATEST_VERSION=$(curl -s https://api.github.com/repos/basekick-labs/arc/releases/latest | grep tag_name | cut -d '"' -f 4 | sed 's/v//')
wget https://github.com/basekick-labs/arc/releases/download/v${LATEST_VERSION}/arc_${LATEST_VERSION}_amd64.deb
sudo dpkg -i arc_${LATEST_VERSION}_amd64.deb
sudo systemctl enable arc && sudo systemctl start arc
curl http://localhost:8000/health
```

**ARM64:**

## Verify the RPM signature

From 26.09.4 the Arc RPMs (`arc` and `arc-fips`) are signed with the Basekick Labs package key. Recent rpm releases, such as rpm 6.1 on Fedora 45, refuse to install a package whose key has not been imported, so import the key once before installing:

```bash
sudo rpm --import https://github.com/basekick-labs/arc/releases/latest/download/RPM-GPG-KEY-basekick
```

The key is also in the repository at [`deploy/packaging/RPM-GPG-KEY-basekick`](https://raw.githubusercontent.com/Basekick-Labs/arc/main/deploy/packaging/RPM-GPG-KEY-basekick). Its fingerprint is:

```text
3E39 9CF8 F5D2 EF9A A9A5  36EF 7629 7AF0 8CBA B6FE
```

Check a downloaded package against it:

```bash
rpm -K arc-<version>-1.x86_64.rpm
# arc-<version>-1.x86_64.rpm: digests signatures OK
```

RPMs up to 26.09.3 are unsigned. `dnf install ./arc-<version>-1.x86_64.rpm` still installs them, with a warning; `rpm -i` refuses them where rpm enforces signatures.

## Get your admin token

When Arc starts for the first time, it generates an admin token.

<Callout type="warn" title="Save This Token">
Copy this token immediately - you won't see it again!
</Callout>

```bash
sudo journalctl -u arc | grep -i "admin"
```

You should see:

```text
======================================================================
  FIRST RUN - INITIAL ADMIN TOKEN GENERATED
======================================================================
  Admin API token: <admin-api-token>
======================================================================
```

The token is the value after `Admin API token:` (44 characters when Arc generates it). Save it:

```bash
export ARC_TOKEN="<admin-api-token>" ARC_ENDPOINT=http://localhost:8000
```

Export `ARC_ENDPOINT` with the token: arcli reads the two together from the environment, and fails with `ARC_TOKEN needs ARC_ENDPOINT` when only the token is set.

## Storage backends

<Tabs items={['Local', 'AWS S3', 'MinIO', 'Azure Blob']}>
  <Tab value="Local">

**Local Filesystem** - Default, data stored on disk.

Edit `/etc/arc/arc.toml`:

```toml
[storage]
backend = "local"
local_path = "/var/lib/arc/data"
```

Or via environment:

```ini
ARC_STORAGE_BACKEND=local
ARC_STORAGE_LOCAL_PATH=/var/lib/arc/data
```

<Callout type="warn" title="The systemd unit sets the storage path">
The packaged `arc.service` sets `Environment="ARC_STORAGE_LOCAL_PATH=/var/lib/arc/data"`, and environment variables override `arc.toml`. A `local_path` edited in `/etc/arc/arc.toml` is ignored: the log still shows `Storage backend initialized backend=local path=/var/lib/arc/data`. See [Move the data directory](#move-the-data-directory).
</Callout>

  </Tab>
  <Tab value="AWS S3">

**AWS S3** - Production cloud storage.

Edit `/etc/arc/arc.toml`:

```toml
[storage]
backend = "s3"
s3_bucket = "arc-production"
s3_region = "us-east-1"
# Use IAM roles or environment variables for credentials
```

Environment variables:

```ini
ARC_STORAGE_BACKEND=s3
ARC_STORAGE_S3_BUCKET=arc-data
ARC_STORAGE_S3_REGION=us-east-1
AWS_ACCESS_KEY_ID=your_key
AWS_SECRET_ACCESS_KEY=your_secret
```

<Callout type="idea" title="IAM Roles">
On EC2, use IAM instance profiles for automatic credential management.
</Callout>

  </Tab>
  <Tab value="MinIO">

**MinIO** - Self-hosted S3-compatible storage.

Edit `/etc/arc/arc.toml`:

```toml
[storage]
backend = "minio"
s3_bucket = "arc"
s3_endpoint = "minio.local:9000"
s3_access_key = "minioadmin"
s3_secret_key = "minioadmin123"
s3_use_ssl = false
s3_path_style = true
```

  </Tab>
  <Tab value="Azure Blob">

**Azure Blob Storage** - For Azure deployments.


Edit `/etc/arc/arc.toml`:

```toml
[storage]
backend = "azure"
azure_container = "arc-data"
azure_account_name = "your_account"
azure_account_key = "your_key"
```

  </Tab>
</Tabs>

## Service management

### Start/stop/restart

```bash
sudo systemctl start arc      # Start
sudo systemctl stop arc       # Stop
sudo systemctl restart arc    # Restart
sudo systemctl status arc     # Status
```

### View logs

```bash
sudo journalctl -u arc -f            # Follow logs
sudo journalctl -u arc -n 100        # Last 100 lines
sudo journalctl -u arc --since "1 hour ago"
```

### Enable/disable auto-start

```bash
sudo systemctl enable arc     # Enable on boot
sudo systemctl disable arc    # Disable on boot
```

## Configuration

Configuration file: `/etc/arc/arc.toml`

```bash
sudo nano /etc/arc/arc.toml
sudo systemctl restart arc
```

### Common options

```toml
[server]
port = 8000

[storage]
backend = "local"
local_path = "/var/lib/arc/data"  # ignored under the packaged systemd unit, which sets ARC_STORAGE_LOCAL_PATH

[auth]
enabled = true

[compaction]
enabled = true
hourly_enabled = true
daily_enabled = true

[wal]
enabled = false  # Enable for zero data loss
sync_mode = "fdatasync"

[log]
level = "info"
format = "json"
```

See [Configuration Overview](/arc/configuration/overview/) for all options.

## Data directory

| Installation Type | Default Data Directory |
|-------------------|------------------------|
| Package install   | `/var/lib/arc/data`    |
| Source build      | `./data/arc`           |

### Move the data directory

The package's systemd unit sets the local storage path with `ARC_STORAGE_LOCAL_PATH`, which takes precedence over `local_path` in `/etc/arc/arc.toml`. To store data somewhere else, stop Arc, copy the existing data, and override the variable in a drop-in:

```bash
sudo systemctl stop arc
sudo mkdir -p /srv/arc
sudo cp -a /var/lib/arc/data /srv/arc/data
sudo chown -R arc:arc /srv/arc
sudo systemctl edit arc
```

In the editor, add:

```ini
[Service]
Environment="ARC_STORAGE_LOCAL_PATH=/srv/arc/data"
```

Save, then start Arc and confirm the path:

```bash
sudo systemctl start arc
sudo journalctl -u arc | grep "Storage backend initialized"
```

Arc does not move data by itself. Skip the `cp` on a fresh install and create the empty directory instead.

## Updating Arc

<Tabs items={['Debian/Ubuntu', 'RHEL/Fedora', 'Arch Linux', 'Source']}>
  <Tab value="Debian/Ubuntu">

```bash
# Automatic update to latest version
LATEST_VERSION=$(curl -s https://api.github.com/repos/basekick-labs/arc/releases/latest | grep tag_name | cut -d '"' -f 4 | sed 's/v//')
wget https://github.com/basekick-labs/arc/releases/download/v${LATEST_VERSION}/arc_${LATEST_VERSION}_amd64.deb
sudo dpkg -i arc_${LATEST_VERSION}_amd64.deb
sudo systemctl restart arc
```

Up to 26.09.x, a `.deb` upgrade replaces `/etc/arc/arc.toml` with the packaged file, discarding your edits. Copy the file before upgrading and reapply your changes afterwards. From 27.01.1 the `.deb` keeps an existing `/etc/arc/arc.toml`.

  </Tab>
  <Tab value="RHEL/Fedora">

```bash
# Automatic update to latest version
LATEST_VERSION=$(curl -s https://api.github.com/repos/basekick-labs/arc/releases/latest | grep tag_name | cut -d '"' -f 4 | sed 's/v//')
sudo rpm --import https://github.com/basekick-labs/arc/releases/latest/download/RPM-GPG-KEY-basekick
wget https://github.com/basekick-labs/arc/releases/download/v${LATEST_VERSION}/arc-${LATEST_VERSION}-1.x86_64.rpm
sudo dnf upgrade -y ./arc-${LATEST_VERSION}-1.x86_64.rpm
sudo systemctl restart arc
```

The `rpm --import` is needed once, when upgrading from 26.09.3 or earlier. An edited `/etc/arc/arc.toml` is kept across upgrades; the packaged file is written next to it as `arc.toml.rpmnew`.

  </Tab>
  <Tab value="Arch Linux">

```bash
# Automatic update to latest version
LATEST_VERSION=$(curl -s https://api.github.com/repos/basekick-labs/arc/releases/latest | grep tag_name | cut -d '"' -f 4 | sed 's/v//')
wget https://github.com/basekick-labs/arc/releases/download/v${LATEST_VERSION}/arc-${LATEST_VERSION}-1-x86_64.pkg.tar.zst
sudo pacman -U arc-${LATEST_VERSION}-1-x86_64.pkg.tar.zst
sudo systemctl restart arc
```

Your edited `/etc/arc/arc.toml` is preserved across upgrades; if the packaged default changed, pacman writes it as `arc.toml.pacnew`.

## Uninstalling

<Tabs items={['Debian/Ubuntu', 'RHEL/Fedora', 'Arch Linux']}>
  <Tab value="Debian/Ubuntu">

```bash
sudo systemctl stop arc
sudo dpkg -r arc

# Optional: Remove data
sudo rm -rf /var/lib/arc /etc/arc
```

  </Tab>

sudo rpm -e arc

```

  </Tab>
  <Tab value="Arch Linux">

sudo pacman -R arc   # stops and disables the service automatically

# Optional: Remove data
sudo rm -rf /var/lib/arc /etc/arc
```

## Troubleshooting

### Arc won't start

```bash
# Check logs
sudo journalctl -u arc -n 50

# Check port availability
sudo lsof -i :8000
```

### Permission errors

```bash
sudo mkdir -p /var/lib/arc/data
sudo chown -R arc:arc /var/lib/arc
```

### Memory issues

Override in `/etc/arc/arc.toml`:

```toml
[database]
memory_limit = "4GB"
max_connections = 16
thread_count = 8
```
